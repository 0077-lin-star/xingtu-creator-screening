# Excel 字段与呈现规范

## 工作簿结构

默认以达人明细为交付主体，整洁、美观、简洁，供用户自行复核。两张工作表足够：

1. **达人明细**：首表，列出全部初筛基本匹配候选，保留原始26列及顺序。按基本适配程度排序，价格带/销量作为同等适配时的加分，不因偏差或待用户复核而移出表。上方简短注明项目、采集日期、初筛数量和“供用户复核”。不往26列插入状态/审计列。严重不符者默认不放进用户表。
2. **资料说明**：按账号ID记录一句保留理由、待用户复核点、价格/销量偏差（如有关）、指标来源/窗口及真实缺失原因。预估CPM等没有对应原始列的必要数值放这里。截图仍嵌入明细单元格，不用链接跳转。

不默认增加“最终通过”总览或复杂评分页。用户要求仅一张表时，可将简短说明放在明细表下方的独立区域，仍不改26列表头；详细来源保留运行记录。用户要求全量输入名单时按指定范围交付并标明明显不符原因。

每个保留候选默认四张局部截图：粉丝年龄、观众八大人群、粉丝性别、近15条播放表现。200个候选约800张。只有明确严重不符且不交付的账号可以停止采图；价格/销量偏差、缺商单或等待用户判断不构成跳过截图与联系方式的理由。不得只补前几行，真实无法取得时写具体原因，不冒称完整。

候选是初筛结果，不冒称全部条件已核实或品牌已选用。双女性条件项目仍读取两项可见数值，女性截图只放粉丝性别；观众数值和差异放资料说明。预估与自然实际指标分开。资料缺失不自动删掉基本匹配候选。

初筛候选为0时如实报告没有发现基本匹配账号，不填虚构示例。已有基本匹配但尚未终审核实的候选不能被清空成0。公司需求需要时另列“制作公司”，记录真实身份、案例/归属及商务联系，不强填达人画像、不计入达人数量。

## 原始 26 列

| 序号 | 原始表头 | 填写规则 |
| --- | --- | --- |
| 1 | 达人昵称 | 实际账号昵称 |
| 2 | 账号id | 文本格式，完整保留ID；在资料说明标明星图ID/抖音号等类型，不拼接到数值、不在长ID中插入换行 |
| 3 | 达人类型 | 页面标签；自行判断需注明 |
| 4 | 主页链接 | 可点击的已核实链接 |
| 5 | 达人粉丝量（万） | 标准化数值；页面已为万的不再除以10000；保留粉丝/粉丝指数原标签与展示精度 |
| 6 | 粉段结构（截图） | 仅嵌入一张粉丝画像的年龄分布局部截图，不放观众年龄图 |
| 7 | 八大人群占比（截图） | 仅嵌入一张观众画像的八大人群局部截图，不放粉丝八大人群图；目标条件与原值另存资料说明页 |
| 8 | 核心女性占比（综合粉丝、看播人群画像）需大于50% | 嵌入一张粉丝画像的性别分布截图，清楚显示女性比例。历史表头不是统一门槛；筛选口径按项目，粉丝/观众数值分别保留在总览或资料说明页，不求平均 |
| 9 | 达人报价 | 数值，注明币种、视频规格、报价日期；多规格不能随意选择 |
| 10 | 返点（达人对内返点%） | 仅填写有来源的商务信息，未知留空；百分比格式 |
| 11 | 预估结算价格（平台价格*返点*0%服务费） | 用户已明确先留空、后续手填；禁止依据原始表头算式创建公式，在明细上方说明手填 |
| 12 | 达人是否能跨月保价 | 有明确承诺才填“是”及期限；未知写“待确认”，不能用当前报价推断 |
| 13 | 商单播放量中位数（万）（排除广告流量） | 自然商单播放中位数；记录样本与窗口；不能确认排除广告则留空 |
| 14 | 自然量CPM（排除广告流量） | 页面符合口径的数据或有明确成本分子的合法计算；未知留空 |
| 15 | CPE（排除广告流量） | 保留互动口径；未知留空 |
| 16 | 商单完播率（排除广告流量） | Excel 百分比数值，例如 5% 存 0.05 |
| 17 | 完播CPM | 平台值或同样本合法计算；无法确认口径则留空 |
| 18 | 近15条播放曲线截图 | 在此单元格嵌入平台实际图表局部截图，保留日期轴、数据及排除营销流量状态；不足 15 条标明数量 |
| 19 | 月涨粉率 | 百分比数值，保留负值与统计月份/窗口 |
| 20 | 月连接用户数（万） | 确认页面指标含义后映射，人数转换为万 |
| 21 | 月深度用户数（万） | 确认是用户要求的月深度链接指标；人数转换为万 |
| 22 | 合作客户（美妆类选品，考虑过往是否有带货美妆品牌） | 据可见合作记录或用户资料；美妆是历史项目提示，本次按项目品类；“合作”不能无证据写成“带货” |
| 23 | 达人侧的植入想法（如有） | 仅填写达人实际提供的想法并注明来源；不能把模型创意当达人发言 |
| 24 | 达人微信/联系方式 | 公开商务或用户提供来源；标注达人/MCN归属、微信/电话/未注明类型标识；无结果可简写实际原因，详细入口记录在资料说明，不猜测 |
| 25 | 是否有MCN | 是/否/未知；没有显示不等于没有 |
| 26 | MCN名称 | 有证据才填写；未知留空 |

保留原始表头用于兼容用户流程。明细上方或资料说明写本次有效条件，使第8列历史“50%”不变成统一淘汰线。用户之后授权改表头时再改。

## 视觉规范

- 默认白底、深蓝表头、浅灰交替行，最多一个强调色；避免大面积鲜艳填色、装饰图标和多层合并表头。
- 使用易读中文字体、10–11 磅正文，数字右对齐、文字左对齐。表头自动换行，内容行按需换行；不把全部 26 列硬缩到一屏。
- 明细冻结表头与前两列，启用筛选；资料说明保持紧凑。数据区不合并单元格。
- 数值保持数值类型并用格式表示“万”、百分比和货币；空缺不填 0。账号 ID 和联系方式保持文本。
- 截图直接放入明细对应单元格，按实际图片设置列宽和行高，图片不越过单元格、不遮挡邻列。优先原生单元格图片；工具仅支持图片对象时，将图片完整锚定在该格内，并设置随单元格移动和缩放，不能用跳转链接代替。
- 只截所需信息：保留图表标题、坐标轴、图例、数值及必要的选中状态；裁去导航、侧栏、无关图表、大块空白。截图前移开悬浮提示，避免遮挡数据。允许裁剪和等比缩放真实截图，不重画、不补造数值。按上表每个截图字段仅放一张，明确标记粉丝或观众来源。
- 结算价留空并以浅色输入底纹提示可手填。其余缺失项在资料说明页逐账号、逐字段记录具体原因，不能混淆未采集、平台不展示、无样本和需商务确认。联系方式未取得时用简短文字说明；图像无法取得时在相应格显示原因。数值空格仍保持空值，禁止填0。
- 推荐理由与限制保持简短，通常各1—2句；来源、时间窗、详细解释放资料说明页。用户未要求时不额外添加批注。

## 交付检查

确认文件可打开、26列名称顺序正确、ID保持文本、唯一初筛候选计数准确、结算价无公式无数值、百分比/万单位正确、四图与账号对应、链接可用、长文本不遮挡。使用真实资料检查版式，不把模拟账号交付。

明细每一行都核对四图与公开联系信息。只有严重不符且不交付者仅记内部日志；价格/销量未满足或有复核点的保留候选仍采全。核对图中当前选择为粉丝或观众，避免平台保留上次状态造成错图。用户最终评价尚未发生，不能声称已接受。

## 成表前逐行资料清单

执行 [联系与截图操作流程](contact-and-screenshot-workflow.md) 的规范化映射、补采和导出核对。联系方式X列应包含实际查看微信结果及简介补充；不能仅写“主页有联系入口”代替点击读取。所有候选F/G/H/R共4×N个图位逐项核对保存文件，记录已采未嵌图与未采图的区别。源字段缺键或文件缺失不自动生成“平台未展示”。

在运行记录按ID维护四图取得状态、联系入口检查结果、基本匹配依据、空值原因和来源时间。每一行都核对，不能只检查首行。所有字段取得或说明真实缺失，只能称“采集已处理”；缺失说明不能使资料变成齐全。四图齐全必须真实取得4张。结算价按用户要求空白，不算漏采。

- 排序先对账号记录完成，再按同一ID绑定数值、四图与联系信息；不要先贴图再只重排文字行。筛选/排序后图像行为取决于Excel实现，导出后检查实际锚定，不把“随行移动缩放”当作已验证任意排序安全的证明。
- 图片裁切保留标题、分类/轴、读数和必要状态；仅放巨大整页缩略图不算有效局部截图。每张图单独确认可读性，不以统一高度挤压比例。
- 保存后检查所有图片绑定与缺失说明；视觉检查覆盖所有工作表、明细首/中/末行和长表头，不只看首行。无法在原生Excel验证的行为应如实注明。
- 单元格未知值保持空白，不填0、连字符或假公式凑满。结算列包括样表在内均无数值、无公式；其余数据和数字格式不受留空列影响。
